# Defect taxonomy

All sources accessed **2026-10-25**. S-numbers refer to the citations and evidence limitations in `literature.md`; links below point directly to opened sources. This table is a defensive synthesis. A property mapping means a planned check may expose an instance, not that it completely detects the class. Fixes are recommendations, not verified patches to current benchmark releases.

P1 trivial baselines; P2 grader isolation; P3 sandbox leakage; P4 mutation rejection; P5 reference repeatability; P6 content-neutral judge invariance; P7 difficulty calibration.

| Class | Short definition | Sources reporting or discussing it | Typical fix | Hackproof detection / limit |
|---|---|---|---|---|
| Vacuous success / no-op reward | Reward without the task's intended capability or required action | [S07 ABC](https://arxiv.org/html/2507.02825v5), [S03 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/) | Run null/empty controls; clarify legitimate refusal and impossible-task semantics | P1; nonzero null reward needs task-specific interpretation |
| Shared evaluator authority | Submission can influence scorer process, dependencies or filesystem | [S02 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks/), [S08 METR](https://metr.org/blog/2025-06-05-recent-reward-hacking/), [S09 METR](https://metr.org/blog/2026-05-19-frontier-risk-report/) | Separate scoring authority; immutable infrastructure; controlled artifact transfer | P2; configuration inspection alone cannot establish complete isolation |
| Runtime answer/reference exposure | Gold data or reference implementation is accessible in the agent sandbox | [S03 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/), [S05 Terminal Wrench](https://arxiv.org/abs/2604.17596) | Keep privileged material outside the sandbox; inspect built images | P3; scope must include mounted and generated material |
| Repository-state leakage | Task checkout includes information from after the intended task date | [S12 issue #465](https://github.com/SWE-bench/SWE-bench/issues/465), [S13 issue #93](https://github.com/scaleapi/SWE-bench_Pro-os/issues/93) | Build a sanitized historical snapshot; validate actual image provenance | P3; historical reports do not establish present vulnerability |
| Mutable correctness checks | Agent-controlled test or scoring artifacts change what counts as success | [S14 ImpossibleBench](https://arxiv.org/abs/2510.20270), [S15 EvilGenie](https://arxiv.org/abs/2511.21654) | Grade independently using protected checks; validate artifact integrity | P2/P3; static file permissions are only part of the boundary |
| Fabricated metrics / result-channel confusion | Scorer trusts metrics or loosely parsed output supplied by the submission | [S02 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks/), [S05 Terminal Wrench](https://arxiv.org/abs/2604.17596) | Compute metrics externally; require strict schemas and authenticated provenance | P2 partially, P4 for selected negative controls; parser correctness needs dedicated tests |
| Unsafe interpretation of output | Grader executes data from an untrusted source | [S03 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/), [S04 BenchJack](https://github.com/benchjack/benchjack) | Parse data with bounded schemas; separate execution authority | P2 partially; full parser security is not covered by Hackproof |
| Weak matching / skipped conditions | Comparisons or control flow accept answers without checking requirements | [S03 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/) | Validate every required condition; test empty, malformed and near-miss outputs | P1/P4 for exercised cases |
| Incomplete test coverage | Incorrect or partial solutions satisfy a narrow test suite | [S07 ABC](https://arxiv.org/html/2507.02825v5), [S11 OpenAI](https://openai.com/index/separating-signal-from-noise-coding-evaluations/) | Requirement-linked tests, meaningful mutants, held-out cases | P4; surviving mutants are evidence, killed mutants do not prove completeness |
| Numerical distribution / tolerance gaps | Correctness checks miss input regimes or accept inappropriate numerical error | [S16 KernelBench-Verified](https://arxiv.org/abs/2607.16241), [S02 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks/) | Diverse hidden distributions; justified tolerances and trusted references | P4 through domain-specific adapters; generic mutations are insufficient |
| Overstrict grading / incomplete task specification | Valid alternatives fail, or hidden requirements are absent from the prompt | [S10 OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/), [S11 OpenAI](https://openai.com/index/separating-signal-from-noise-coding-evaluations/) | Independent valid solutions; reconcile prompt, oracle and tests | Not covered by Hackproof generally; P5 checks only the supplied reference |
| Training contamination | Evaluation problems or solutions were learned before the run | [S10 OpenAI](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/) | Fresh/private tasks; provenance and exposure audits | Not covered by Hackproof; P3 covers runtime access only |
| Judge instruction interference | Evaluated content influences judge instructions rather than supplying task evidence | [S03 RDI](https://rdi.berkeley.edu/blog/trustworthy-benchmarks-cont/), [S04 BenchJack](https://github.com/benchjack/benchjack) | Treat content as untrusted data; constrain and independently validate judgments | Not fully covered; P6 neutral perturbations are a different test |
| Monitor observability dependence | Detection quality changes with the information available in a trajectory | [S05 Terminal Wrench](https://arxiv.org/abs/2604.17596), [S15 EvilGenie](https://arxiv.org/abs/2511.21654) | Validate monitoring under actual logging conditions; retain human review samples | Not covered by Hackproof; removing reasoning changes information, not just style |
| Environment drift / invalid setup | External dependencies or task setup prevent intended execution | [S07 ABC](https://arxiv.org/html/2507.02825v5) | Pin dependencies; reset and validate setup; preserve reproducible snapshots | P5 can expose repeatability failures; stable broken setups also need semantic review |
| Performance baseline unfairness | Apparent speedup depends on weak baselines or unmatched numerical settings | [S16 KernelBench-Verified](https://arxiv.org/abs/2607.16241) | Match precision and hardware settings; measure memory and timing independently | Not covered by Hackproof's seven properties |
| Trusted-checker unsoundness | Checker logic or runtime accepts invalid proof artifacts | [S17 Lean postmortem](https://leodemoura.github.io/blog/2026-8-24-postmortem-for-the-kernel-soundness-bug-hunt/) | Update dependencies; export and independently recheck; diversify checkers | Not covered by Hackproof; P2/P4 offer only boundary and regression evidence |
| Misestimated uncertainty / difficulty | Passing-test observations are summarized with unsuitable estimators or sampling rules | [S18 Chen](https://arxiv.org/html/2107.03374v2), [S19 Brown–Cai–DasGupta](https://web.pdx.edu/~ihd/stat563.S17/brown.pdf), [S20 Wald reprint](https://link.springer.com/chapter/10.1007/978-1-4612-0919-5_18) | Use justified estimators; record sampling assumptions and stopping policy | P5/P7; original SPRT threshold derivation remains UNVERIFIED in this review |

Two proposed checks need stronger direct evidence than this map supplies: neutral-perturbation judge invariance (P6) and the complete Beta-posterior/SPRT calibration protocol (P7). Their inclusion in Hackproof is a design proposal, not a result demonstrated by the reviewed audits. [S01](https://epoch.ai/gradient-updates/state-of-rl-envs), [S15](https://arxiv.org/abs/2511.21654), [S19](https://web.pdx.edu/~ihd/stat563.S17/brown.pdf), [S20](https://link.springer.com/chapter/10.1007/978-1-4612-0919-5_18); accessed 2026-10-25.
